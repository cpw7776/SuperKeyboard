# Migration: AI Dev Workflow Kit v5.11 → v5.12

> **When to use this:** Your project is on v5.11 (`docs/KIT_VERSION` reads `5.11`) and you want v5.12 — "parallel-testing adaptiveness + convergent-retro fixes." Three changes:
> 1. **`feature-lifecycle.md` §4.1p — adapt, don't dictate.** The parallel concurrency `N` is derived at runtime from the host machine + project, never a fixed number; the cap is your machine's ceiling (not a kit default); and the agent now **surfaces the recommended N to you as a quick pick** instead of silently running it.
> 2. **Rule-numbering canonical fix.** The `v5.9-to-v5.10` migration previously contradicted `db-precondition.md` on which rule moves in a Pattern-B/parallel collision. Now consistent everywhere: kit-origin rule keeps its vanilla number, project extension goes to the tail (parallel = Rule 23, Pattern B = Rule 24).
> 3. **Fingerprint table extended** through v5.11 in `upgrade-kit.md`.
>
> **Philosophy:** mostly tooling/guidance. The load-bearing §4.1p adaptiveness lands **outside** the `parallel-testing-capacity` slot, so it reaches you even if you already filled that slot. Tooling files wholesale-refresh if vanilla.
>
> **When NOT to use this:** On v5.10 or earlier — run prior migrations first. Starting fresh — README Quick Setup drops you on v5.12.
>
> **Model:** `sonnet`, unless Phase 2's slot-aware edit hits a hand-edited feature-lifecycle region (then `opus`).
>
> **Stop points:** Two — after the state audit (Phase 1), and before the final commit (Phase 5).

**Inputs:** **PROJECT_ROOT** and **NEW_KIT_ROOT** (the v5.12 kit). Never touch anything outside `PROJECT_ROOT`.
