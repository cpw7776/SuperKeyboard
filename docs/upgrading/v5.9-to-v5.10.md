# Migration: AI Dev Workflow Kit v5.9 → v5.10

> **When to use this:** Your project is on v5.9 (`docs/KIT_VERSION` reads `5.9`) and you want to land on v5.10 — the "capability-gated parallel browser testing" release. It lets Phase 4 run multiple testing agents **concurrently** on a capable machine, each isolated on its own browser session + dev-server port + test user.
>
> **What changes:**
> 1. **`testing-agent.md`** gains parallel-run isolation (new §0.5) and **mode-scoped RAM-hygiene + teardown** — the old global `pkill` / `agent-browser close --all` were fine sequentially but would kill sibling agents in parallel, so they're now split into solo vs parallel variants. Plus Rule 23. (v3.1 → v3.2.)
> 2. **`feature-lifecycle.md`** gains a `4.1p Parallel testing mode` subsection with the concurrency math and a new `[CUSTOMIZE] parallel-testing-capacity` slot (your per-agent memory budget + **test-user pool**), and the "sequential only" rules are clarified to exempt read-only Phase 4 testing agents.
> 3. **`create-testing-agent.md`** gains `parallel_safe` / `parallel_isolation` plan-config fields + a classification decision guide. (v3 → v3.1.)
>
> **The load-bearing idea:** a shared dev database is fine; the clash is **two agents acting as the same user at once**. Concurrency is therefore capped by how many distinct test logins your project has, and the orchestrator hands each parallel agent its own.
>
> **Behaviour is unchanged until you opt in.** All existing test plans stay `parallel_safe`-unset → sequential. The isolation safety net only activates in parallel mode. A single-login project never parallelizes. You can take this release purely for the safety net and never mark a plan.
>
> **When NOT to use this:** You're on v5.8 or earlier — run the prior migrations first (the upgrade-kit prompt chains them). Starting fresh — README Quick Setup drops you on v5.10 directly.
>
> **Model:** `opus` — the `testing-agent.md` §0/§8 merge needs judgment if your project hand-edited the RAM-hygiene/teardown blocks (e.g. added project-specific process names to the `pkill` patterns).
>
> **Stop points:** Two — after the state audit (Phase 1), and before the final commit (Phase 4).

**Inputs needed:**
- **PROJECT_ROOT:** path to the project you're upgrading
- **NEW_KIT_ROOT:** path to the v5.10 kit (where this prompt lives)

The migration agent never touches anything outside `PROJECT_ROOT`.

## What this migration deliberately does NOT do

- **It does not change any existing test plan's behaviour.** Unmarked plans run sequentially exactly as before. Parallelism is opt-in per plan.
- **It does not enable parallelism on a single-login project.** The concurrency math caps N at the distinct-login count.
- **It does not touch the forward lifecycle's gates, phases, or sub-agent set** beyond Phase 4's testing dispatch. The four Phase 5 gates are unchanged.
