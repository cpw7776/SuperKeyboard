# Migration: AI Dev Workflow Kit v5.13 → v5.14

> **When to use this:** Your project is on v5.13 (`docs/KIT_VERSION` reads `5.13`) and you want v5.14 — **"the Phase 5 self-improvement retro becomes an unconditional, merge-blocking Retrospective Gate, and gains Gap C (implementation/code lessons)."** Three connected changes:
> 1. **Phase 5.1 retro is now UNCONDITIONAL** — no longer gated on "if manual testing revealed bugs." It's a sweep over the union of every manual-test finding and every `fix(` commit of the phase, with a recorded per-finding decision (close via Gap A/B/C, or name it as deliberately-not-lessoned).
> 2. **A verbatim `RETROSPECTIVE GATE:` block** (same idiom as the Documentation Gate) is added at the close of Phase 5.1 and becomes the **FIRST of five** merge-blocking gates at Phase 5.8. The gate count rises **four → five** everywhere.
> 3. **Gap C — implementation/code lessons.** A new third autopsy bucket captures durable code lessons (recurring bug-class, project gotcha, architectural anti-pattern) into a NEW append-only guide, **`docs/context/Implementation_Patterns.md`** — the code-side mirror of `Unit_Test_Writing_Guide.md`. Phase 3 is wired to **read it before writing code**, the same way the TDD red step reads the test guide. If your project already has its own code/implementation guide, point Gap C at that one instead of adding the new file.
>
> **Why this change:** the conditional retro got skipped — whole epics shipped with their manual-test misses un-retro'd (bugs fixed, durable lessons never written). The Documentation Gate always runs precisely *because* it's an enforced gate; this gives the retro the same enforcement. The "deliberately NOT lessoned" line is what keeps the gate honest on polish-only epics (a named line, not a silent skip) instead of teams wanting to skip it.
>
> **Universal-drop-in reminder:** this migration *guides*; it does not prescribe one outcome. Every file it touches, the agent reconciles against THIS project's customization state (vanilla → refresh, structurally-divergent → apply surgically, slotted/hand-edited → merge or surface). The change is **stack-agnostic** — the retro sweep, the Gap A/Gap B vocabulary, and the gate idiom apply identically to a Next.js app, a Python pipeline, or a native-Android project. The `fix(` commit convention is the only assumption; a project that uses a different fix-commit prefix maps the `git log --grep` to its own.
>
> **When NOT to use this:** On v5.12 or earlier — run prior migrations first. Starting fresh — README Quick Setup drops you on v5.14.
>
> **Model:** `sonnet`, unless Phase 2 hits a hand-edited `feature-lifecycle.md` Phase 5 region (then `opus` — the edits must land around the customization without breaking the gate logic).
>
> **Stop points:** Two — after the state audit (Phase 1), and before the final commit (Phase 4).

**Inputs:** **PROJECT_ROOT** and **NEW_KIT_ROOT** (the v5.14 kit). Never touch anything outside `PROJECT_ROOT`.

## What this migration does NOT do

- It does not change Gap A / Gap B autopsy mechanics, the `test-suite-retro.md` / `testing-retro.md` prompts, or any tier-propagation logic — only the *trigger* (conditional → unconditional), the *enforcement* (new gate block), and the *new Gap C bucket*.
- It does not add a sub-agent — the Retrospective Gate is authored by the main agent, which already owns all of Phase 5.
- It does not force the kit's `Implementation_Patterns.md` on a project that already has its own code guide — Gap C points at whichever guide the project keeps.
- It does not prescribe how any file lands — the in-project agent reconciles each against this project's own customization state.
- It updates **all three retro-running flows** this release (`feature-lifecycle.md`, `bugfix.md`, `reconcile-change.md`) so Gap C has parity across them — see Phases 2 and 2.6. It does NOT change Gap A / Gap B mechanics in any of them.
