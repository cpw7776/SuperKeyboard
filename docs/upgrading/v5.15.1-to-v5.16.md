# Migration: AI Dev Workflow Kit v5.15.1 → v5.16

> **When to use this:** Your project is on v5.15.1 (`docs/KIT_VERSION` reads `5.15.1`) and you want v5.16 — **"upgrade-system robustness + a native-mobile worked example."** This release improves the *upgrade machinery and prompt guidance*; it changes **nothing** in the forward lifecycle (no phase, gate, or sub-agent change). The wins land on the **next** upgrade this project runs, and for any non-web project, in cleaner testing-agent generation.
>
> Five changes, all in tooling/prompt files:
> 1. **`upgrade-kit.md` fingerprint anchors re-anchored** off `[CUSTOMIZE]`-slot text (v5.12) and the divergence-prone `testing-agent.md` (v5.8/v5.10) → onto stack-invariant, slot-free content. Plus an "Anchor discipline" preamble.
> 2. **`upgrade-kit.md` Step 1.6** — over-stamped-marker reconciliation (marker ahead of content).
> 3. **`upgrade-kit.md` Step 6** — divergence-aware sanity (EXPECTED-FAIL for rewritten files, not FAIL→STOP).
> 4. **`upgrade-kit.md` Step 2.5 + Step 3** — `[CUSTOMIZE]`-leftover lint, `docs/README.md` identity check, sanctioned wholesale-refresh+reinject strategy.
> 5. **`create-testing-agent.md`** — a native-mobile (Android) worked example appended to the Stack Adaptation section (illustration, not an enforced profile).
>
> **When NOT to use this:** On v5.15 or earlier — run prior migrations first (the corrected v5.14→v5.15 prompt lands you on v5.15.1). Starting fresh — README Quick Setup drops you on v5.16.
>
> **Model:** `sonnet` (mechanical refreshes), unless a hand-edited `upgrade-kit.md` or a structurally-divergent `create-testing-agent.md` needs surgical judgment (then `opus`).
>
> **Stop points:** One — before the final commit (Phase 3). The edits are low-risk refreshes; no mid-flight STOP is needed unless a file is hand-edited and a merge conflicts.

**Inputs:** **PROJECT_ROOT** (the kit root — `upgrade-kit.md` Inputs §3; may be a package subfolder) and **NEW_KIT_ROOT** (the v5.16 kit). Never touch anything outside PROJECT_ROOT.
