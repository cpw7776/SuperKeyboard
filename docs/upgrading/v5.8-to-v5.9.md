# Migration: AI Dev Workflow Kit v5.8 → v5.9

> **When to use this:** Your project is on v5.8 (`docs/KIT_VERSION` reads `5.8`) and you want to land on v5.9. v5.9 is the "ad-hoc reconciliation" release. It adds:
> 1. **`docs/prompts/reconcile-change.md`** — a standalone *reverse-lifecycle* prompt. For when you fixed/added something directly (no PRD, no ADR, no tests-first) and want the project caught up afterwards: backfill the tests, update architecture/PRD/ADR *only if the change touches one*, and sync the context + user-facing docs. It reuses your already-customized `context-docs-agent` and `docs-auditor-agent` **by reference** (run inline, not dispatched), so it inherits your per-project doc surfaces with zero new customization.
> 2. **`.claude/commands/reconcile.md`** — the kit's **first project-level slash command**. A thin wrapper that runs the prompt above when you type `/reconcile`. This is the first time the kit ships anything under `.claude/commands/`, so your project may not have that directory yet — this migration creates it.
>
> **Philosophy:** v5.9 is **purely additive** — two new files, no edits to any existing (and possibly customized) project file. There is nothing to merge and nothing to overwrite. The only risk is the trivial one of dropping the files in the wrong place, which the verification step catches.
>
> **When NOT to use this:** You're on v5.7 or earlier — run the prior migrations first (the upgrade-kit prompt walks the chain). You're starting fresh — `docs/README.md` Quick Setup drops you on v5.9 directly.
>
> **Model:** `sonnet` is sufficient — this migration is two file copies and a version bump. No merge reasoning.
>
> **Stop points:** Two — after the state audit (Phase 1), and before the final commit (Phase 3).

**Inputs needed:**
- **PROJECT_ROOT:** path to the project you're upgrading
- **NEW_KIT_ROOT:** path to the v5.9 kit (where this prompt lives)

The migration agent never touches anything outside `PROJECT_ROOT`.

---

## Phase 1: State Audit (READ-ONLY) — STOP after this phase

**Goal:** Confirm the project is on v5.8 and that v5.9's two files aren't already present.

```
1. Read PROJECT_ROOT/docs/KIT_VERSION.
   Expected: "5.8"
   - If "5.9" or higher: STOP. Already migrated.
   - If "5.7" or lower: STOP. Run docs/prompts/upgrade-kit.md from the new kit — it
     chains the earlier migrations first, then re-invokes this prompt.

2. Confirm v5.9 is NOT already partially applied:
   - PROJECT_ROOT/docs/prompts/reconcile-change.md should NOT exist yet.
   - PROJECT_ROOT/.claude/commands/reconcile.md should NOT exist yet.
   If either exists, surface it and ask the user whether to overwrite (e.g. they
   may have hand-created a /reconcile wrapper that this release supersedes).

3. Note whether PROJECT_ROOT/.claude/commands/ exists at all.
   - Most v5.8 projects will NOT have it (v5.9 is the first command-shipping release).
   - If it exists with other project-local commands, that's fine — this migration only
     adds reconcile.md alongside them.
```

**STOP.** Report: current version confirmed, whether either v5.9 file already exists, and whether `.claude/commands/` exists. Wait for the user before copying.

---

## Phase 2: Copy the two new files (ADDITIVE)

Nothing here merges or overwrites a customized file — both targets are brand-new paths.

```
1. Copy the reverse-lifecycle prompt verbatim:
   cp NEW_KIT_ROOT/docs/prompts/reconcile-change.md PROJECT_ROOT/docs/prompts/reconcile-change.md

   This file is universal — it references your existing .claude/agents/context-docs-agent.md
   and .claude/agents/docs-auditor-agent.md by path, so any [CUSTOMIZE] work you've already
   done in those agents flows through automatically. Do NOT edit reconcile-change.md.

2. Create the commands directory if absent, then copy the command:
   mkdir -p PROJECT_ROOT/.claude/commands
   cp NEW_KIT_ROOT/.claude/commands/reconcile.md PROJECT_ROOT/.claude/commands/reconcile.md

   This is a thin pointer to docs/prompts/reconcile-change.md (project-relative). No
   customization needed — it resolves against whatever project it's run in.
```

**Verify:**
```
- PROJECT_ROOT/docs/prompts/reconcile-change.md exists and is byte-identical to the kit copy
  (diff NEW_KIT_ROOT/docs/prompts/reconcile-change.md PROJECT_ROOT/docs/prompts/reconcile-change.md → empty).
- PROJECT_ROOT/.claude/commands/reconcile.md exists and is byte-identical to the kit copy.
- Open a fresh chat in PROJECT_ROOT and confirm `/reconcile` is now offered (optional sanity check).
```

---

## Phase 3: Stamp + Commit — STOP before committing

```
1. Bump the version marker:
   Write "5.9" to PROJECT_ROOT/docs/KIT_VERSION (replacing "5.8").

2. Re-fingerprint sanity check:
   - docs/prompts/reconcile-change.md present.
   - .claude/commands/reconcile.md present.
   - docs/KIT_VERSION reads "5.9".

3. If your project keeps a docs/KIT_DEVIATIONS.md, no entry is needed — v5.9 adds no
   customizable slots. (Only note something if you chose NOT to adopt /reconcile, e.g. a
   project shape where ad-hoc reconciliation doesn't apply.)
```

**STOP.** Show the user the two new files + the version bump. On approval, commit:

```
chore(kit): upgrade to v5.9 — ad-hoc reconciliation (/reconcile)

- Add docs/prompts/reconcile-change.md (reverse-lifecycle: backfill tests + sync docs after unplanned work)
- Add .claude/commands/reconcile.md (first project-level kit command)
- Bump KIT_VERSION 5.8 → 5.9
```

---

## What this migration deliberately does NOT do

- **It does not touch `feature-lifecycle.md`, `bugfix.md`, the agents, or any context file.** `/reconcile` is standalone and additive — it changes nothing about the existing forward lifecycle.
- **It does not customize anything.** The prompt's per-project behavior comes entirely from the agents it references, which you customized at adoption.
- **It does not register a user-level `/reconcile`.** That's a personal-machine convenience (`~/.claude/commands/`), outside any project. Add one yourself if you want `/reconcile` available even in projects not yet on v5.9.
